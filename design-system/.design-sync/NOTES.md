# design-sync — Donel Dev Design System — NOTES

## First sync (2026-07-22)

- `[GENERAL]` Preview decorator bundle fails: `.storybook/preview.tsx` imports `@fontsource/*` CSS files, and the decorator bundler's esbuild call (`lib/source-storybook.mjs`) only configures `.js`/`.json` loaders — no `.css`/`.woff2` loader — so bundling throws `No loader is configured for ".woff2" files`. Result: previews render WITHOUT the storybook decorator's wrapper div (which supplies `background: var(--bg-app)`, `color: var(--text-primary)`, `font-family: var(--font-ui)` on a full-viewport container). Every preview capture shows a white page canvas behind the component instead of the dark app surface the storybook reference shows.
  - **Root cause is NOT a context/provider dependency** — `probe.mjs` confirms this: it "detects" a bogus `R` (a raw internal React reference, not a real bundle export), because the DS ships no actual `*Provider`/`Theme` component. The decorator is a bare presentational `<div>`, not a context provider, so `cfg.provider` cannot fix it (there is no real component to point at).
  - **Accepted as expected, not a converter defect**, after tracing `src/index.ts` and `src/tokens.css`: the package itself never applies `--bg-app` to `html`/`body` — that's intentionally the HOST app's job (`.storybook/preview.tsx`'s own comment confirms the decorator exists specifically to mimic "the real app surface... instead of Storybook's default white canvas"). Grading followed the rubric's canvas-framing exception (§4): every component's own render — colors, borders, text, spacing — is pixel-faithful between storybook and preview; only the page background behind it differs, and it differs by design, not by defect.
  - **Consumer impact — real, not cosmetic**: components with transparent/no background and light-on-dark text (Ghost button, PostItCard/Toast body text using `--text-primary`) are only legible on a dark host canvas. This is now the #1 rule in `.design-sync/conventions.md` — the design agent MUST set the page background to `var(--bg-app)` before placing any component.
  - If a future sync wants the decorator bundle itself to succeed (cosmetic parity in the DS pane's preview cards, not required for fidelity): fork `lib/source-storybook.mjs` into `.design-sync/overrides/source-storybook.mjs`, add `.css`/`.woff2`/`.ttf` loaders (`dataurl` or `file`) to the decorator's esbuild `loader` map (~line 313), declare it in `cfg.libOverrides`. Not done this run — no functional upside found, since the DS doesn't own page chrome anyway.

- `[FONT_MISSING]` "Cascadia Code" — accepted substitute, not sourced. `--font-mono` in `src/tokens.css` is `'JetBrains Mono', ui-monospace, 'Cascadia Code', monospace` — a 4-deep fallback stack. The DS ships JetBrains Mono (via `@fontsource/jetbrains-mono`, confirmed in the bundle), which is the family that actually renders in every observed capture. "Cascadia Code" is a Microsoft-proprietary font never bundled by the DS by design (fallback-only, for a host OS that happens to have it installed) — not a brand family the DS is expected to ship. No action taken; flagged as **action-not-needed** rather than silently dropped.

- `overrides` applied (presentation-only, targeted-rebuilt, grades unaffected): `Modal` and `Toast` → `cardMode: "single"` (portal/overlay components — `[PORTAL?]`/`[GRID_OVERFLOW] escape`), `PhaseChip`, `PostItCard`, `TerminalTab`, `StatusBar` → `cardMode: "column"` (`[GRID_OVERFLOW] wide` — full-width rows: phase-chip row, post-it board, terminal tab bar, shell status bar).

## Re-sync risks

- **Decorator-bundle gap is a standing condition, not a one-time flake.** Any re-sync will re-print `! preview decorator bundle failed` on every build — this is expected and documented above; do not re-diagnose it as new. If `.storybook/preview.tsx` ever adds a REAL context provider (theme switcher, i18n), the "no context needed" conclusion must be re-checked — re-run `probe.mjs` and look for a real exported component name (not a bare `R`/internal reference) before assuming it still doesn't apply.
- **conventions.md's dark-canvas requirement is load-bearing.** If the design agent ever reports illegible Ghost buttons or invisible text, the first thing to check is whether the design applies `var(--bg-app)` to its root container — not a DS bug.
- **`--font-mono`'s "Cascadia Code" fallback**: if a future DS version promotes it to a real shipped family (not just a stack fallback), revisit — right now it's accepted as never-rendered-in-practice.
- **`cardMode` overrides (Modal, Toast, PhaseChip, PostItCard, TerminalTab, StatusBar) are config-only** — no owned preview `.tsx` files exist yet for this DS (all previews are the converter-generated cache twins). A future re-sync that edits any story file re-keys that component's grade automatically; nothing here is hand-forked.
- **No `.design-sync/previews/` overrides exist** — every component ships the auto-generated preview from its story module. If a future component needs an owned `.tsx` (props/composition fix), follow §4a item 3 of the storybook skill.
